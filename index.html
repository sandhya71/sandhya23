Case study

AutoFX: from raw payments to explainable decisions

Client details are confidential, so this shows the architecture and my contribution without names or data.

Microsoft Fabric OneLake and ADLS Gen2 hold the Medallion layers. Azure AI Foundry LLMs and a feature store feed the propensity model, and RAG agents expose results through FastAPI and MCP endpoints.

Problem

A global bank needed to convert more FX payments straight through, without manual handling, using decisions advisors could trust and audit.

What I owned

Medallion pipelines, the ML pipeline integration, the RAG agent workflows, and the DataOps layer: CI/CD, RBAC, lineage and audit telemetry.

Outcome

50M+ events/day processed, an 86% accurate propensity model, and SHAP-based explanations behind every recommendation.

How I work

Built for the 3am failure

Root cause first

From Microsoft support: read the telemetry, reproduce the failure, then fix the cause, not the symptom.

Runbooks over heroics

Every recurring incident becomes a runbook or an automated check, so the next person doesn't start from zero.

Observable by default

Lineage, row-count checks and audit logs are part of the pipeline design, not added after the first outage.

Explainable AI

In regulated domains, a model output needs a reason. I ship SHAP-based explanations with predictions.
